# Decisions

- **Проверка изображений:** перед записью в Blob используем общий `ImageFileRules`.
  Разрешены JPEG (`.jpg`, `.jpeg`, MIME `image/jpeg`), PNG и WebP: этого достаточно для фотографий товаров.
  MPEG не добавляем: это видео, не изображение. SVG и другие форматы пока не поддерживаем.
  Проверяем размер до 5 МиБ, расширение и Content-Type. Пустой Content-Type отклоняем,
  а не подставляем JPEG. Сигнатуру содержимого эта проверка не анализирует.

- **Размер запроса:** POST создания и редактирования товара, а также создания категории
  ограничены 25 МиБ на весь запрос, включая multipart-данные. Лимит одного файла остаётся 5 МиБ.
  Общий лимит не рассчитан на одновременную загрузку всех 11 файлов максимального размера.

- **Частота изменений:** эти три POST используют общий лимит 3 запроса в минуту на аккаунт.
  Редактирование товара без новых файлов тоже учитывается: политика применяется к endpoint,
  без чтения multipart-тела в rate limiter. GET и удаление товара этот лимит не используют.

- **Параллельные загрузки:** singleton `CloudStorageService` допускает две одновременные
  записи изображений. Остальные загрузки отклоняются без очереди. Слот освобождаем в `finally`.

- **Отключение загрузок:** `ImageUploads:Enabled=false` запрещает новые записи изображений.
  Чтение и удаление остаются доступны. В Azure настройку задаём как `ImageUploads__Enabled`.

- **Ответ при превышении частоты:** для MVC-форм возвращаем HTML-страницу с кодом 429
  и заголовком Retry-After. Для существующей политики Auth сохраняем JSON-ответ.

- **Границы защиты:** счётчики частоты и параллельности находятся в памяти одного процесса
  и сбрасываются при его перезапуске. Это не квота объёма и не гарантия отсутствия расходов.
  Прямые запросы к публичным изображениям в Blob не проходят через лимиты приложения.
